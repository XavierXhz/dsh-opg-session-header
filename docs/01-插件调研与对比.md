# 调研与两个插件对比

> 调研时间：2026-10-23 · 环境：dsh `0.2.1-rc.2`、`@earendil-works/pi-ai` 1.3.0、web profile、
> provider `opencode-go`（`https://opencode.ai/zen/go/v1`）、默认模型 `deepseek-v4.1-flash`

## 1. 问题与根因

### 1.1 网关事实（实测）

```text
POST https://opencode.ai/zen/go/v1/chat/completions
无 x-opencode-session → HTTP 400 {"type":"MissingSessionID", ...}
有 x-opencode-session → HTTP 200
```

复现脚本：[`scripts/verify-gateway.mjs`](../scripts/verify-gateway.mjs)。所以这是**真实的上游约束**，
不是 README 传闻。

### 1.2 dsh 0.2.1 已原生覆盖主路径

本机 `@earendil-works/pi-ai@1.3.0` 的 `opencode-headers.js` 会根据 `options.sessionId` 注入
`x-opencode-session`（`openai-completions` 等协议）；`dsh-llm-pi-ai` 也会把
`sessionId: String(options.sessionId)` 透传给 pi-ai。因此普通对话请求本来就有头，插件的价值集中在
**辅助调用**。

### 1.3 缺口：官方自动审查的评审请求没有 sessionId

`@deepseek-ai/dsh-experimental-auto-review/lib/index.js`：

```js
// classifyRisk()
const header = session.requestHeader();
const options = deepFreeze({
  provider: header.config.provider,
  model: header.config.model,
  system: REVIEW_POLICY,
  messages: [{ role: 'user', content: [{ type: 'text', text: reviewUserText(snapshot) }] }],
  temperature: 0, signal,
});                 // ← 没有 sessionId
return readDecision(ctx.llm.stream(options));
```

该包全仓 grep `sessionId` 零命中。评审请求走同一条 `opencode-go` 适配器，但 pi-ai 拿不到会话 id，
于是不带头 → 网关 400 → 该次工具调用以
`Auto review of tool "…" failed; its body was not executed: … MissingSessionID` 失败。

**结论：dsh 官方 Auto review 在 0.2.1-rc.2 + opencode-go 下确实不可用，根因是评审请求缺少会话头。**
上游 dist-tags 仍是 `latest = next = 0.2.1-rc.2`，没有已修复版本。

## 2. 候选 A：`mathangler/dsh-opencode-session-header`

仓库：<https://github.com/mathangler/dsh-opencode-session-header>（MIT，v0.1.3，2026-10-22 推送）

### 机制

不补丁 `globalThis.fetch`、不改文件、不覆盖 service：

1. `inject = ['llm']`，从 `ctx.llm.adapters`（route → `{adapter, ...}` 的 Map）扫描所有 pi-ai 形状适配器；
2. 包住适配器唯一分发口 `PiAiAdapter#streamWithSnapshot(options, snapshot)`，再包
   `snapshot.models.streamSimple(model, context, options)`；
3. 每次调用把会话 id 合并进 `options.headers` 的**副本**，同名静态头大小写不敏感替换。

### 为什么它能覆盖自动审查

- 注入发生在适配器分发点，**与调用方是否传 sessionId 无关**；
- `sessionlessFallback` 默认开启：请求没有会话 id 时，用
  `agents.currentInitiator()?.session?.id` 借「发起这次调用的会话」；
- 自动审查的 `tools/pre-execute` listener 在 agent 驱动内执行，而整轮
  `wakeDriver` 用 `agents.withInitiator(agent, () => kick())` 包住
  （`dsh-agent-loop/lib/index.js:868`）→ 回退能拿到会话 id；
- 范围是 route key 前缀 `opencode-go`（不是 URL），`auto` 取值在 `openai-responses` 上保留
  `session-<uuid>`，避免与 pi-ai 自带 `session_id` 分裂缓存桶。

### 兼容性与状态

- 本机 0.2.1-rc.2 上 45/45 测试通过（真机适配器 + pi-ai `fauxProvider`）；
- 无依赖、无 postinstall、`lib/` 直接运行；
- 风险：★0、单作者、未上 npm；npm 上同名包是**另一个项目**（beihzb，走全局 fetch 补丁），不能按名字装。

## 3. 候选 B：`DMIAOCHEN/dsh-auto-review-plus`

仓库：<https://github.com/DMIAOCHEN/dsh-auto-review-plus>（MIT，v0.1.3，2026-10-07）

### 机制

**fork 0.2.0-rc.2 的官方 auto-review 插件**，接管 `auto` preset：

```yaml
- id: auto-review
  disabled: true          # 必须关掉官方行（registerAuto 是单槽位）
- insert:
    - id: auto-review-plus
```

在官方逻辑上增加：

1. 评审请求带 `sessionId` 与该会话的 `reasoningEffort`（**根因修法**，pi-ai 原生命令头随之生效）；
2. 按会话选择审查模型（provider/model/effort，存自己的 storage domain）；
3. Host Remote API + client 半边：在 Auto 确认弹框里嵌审查模型选择器。

### 兼容性（实测评估）

- **运行时可以在 0.2.1-rc.2 求值**：已用本机 0.2.1 `node_modules` 导入其 `lib/index.js`，导出、domain
  定义、`@Remote` 装饰器、review 纯函数都正常；风险策略文本与 0.2.1 逐字节一致；client bundle 依赖的
  四个 shell 冻结模块与 primitive 导出也都存在。
- **但装不进去**：`peerDependencies` 全部精确钉在 `0.2.0-rc.2`，`dsh-app-boot` 的
  `unmetRequirements` 会跳过该 bundle（除非给精确版本豁免）。
- **需要真实移植**：0.2.1 官方版新增 `workingDirectory` 注入与
  `await ctx.workingDirectory.ensure(agent, signal)`；plus 仍读 `session.header.cwd` 并抛错。`/cd` 之后
  审查环境段会与历史矛盾，且无 header cwd 的会话（0.2.1 有 `defaultDirectory`）每次审查都失败。
  最小改动：peers/devDeps 升 0.2.1-rc.2、`inject` 加 `workingDirectory`、传入 cwd、删掉 header-cwd
  抛错（约 10 行）→ `npm install && npm run build` 重新生成 `lib/index.js` 与 `lib/client.js`。
- 规模：host 1074 行 + client 1684 行 + 149 个 vitest 用例；测试需 `npm install`/vitest，不能直接
  `node --test`。

## 4. 对比

| 维度 | A：mathangler session-header | B：auto-review-plus |
| --- | --- | --- |
| 修复位置 | 适配器分发点补头（绕过根因） | 评审请求补 `sessionId`（根因） |
| 官方 auto-review | 保留，不动它的行 | 停用官方行，接管 `auto` preset |
| 对 0.2.1-rc.2 开箱即用 | ✅ 作者就在该版本验证，45/45 | ❌ peer 精确 0.2.0-rc.2，需豁免 + 移植重建 |
| 覆盖范围 | 评审 + **所有**无 sessionId 辅助调用（title/compaction）+ 主路径双保险 | 仅评审请求 |
| 是否需要 client 半边 | 否 | 是（弹框内审查模型选择器） |
| 代码/维护量 | 2 个 JS 文件、无依赖、可链接安装 | host 1074 + client 1684 行，fork 需跟上游 |
| 升级风险 | 依赖两个 TS `private` 内部面，失败会诊断报告 | 与官方 preset 单槽位竞争、长期 fork 上游 |
| 额外价值 | 无 | 按会话选审查模型、评审携带 reasoningEffort |
| 失败模式 | 挂不上适配器 → 计数/诊断可见，不崩 | 官方 preset 被关但 plus 未加载 → Auto 选项消失 |
| 迁移/退出 | 卸载即还原；上游修复后无痛移除 | 需重新启用官方行、迁移已持久化的 Auto 会话 |

## 5. 结论：选 A 路线，并本地重写

针对我们的目标——**让当前版本（0.2.1-rc.2）的官方自动审查可用**——A 更合适：

1. **开箱兼容当前版本**，不需要豁免、不需要重新构建、不需要停用官方插件；
2. **覆盖面更大**：除自动审查外，session title / compaction 等辅助调用同样受益；主路径是双保险；
3. **侵入最小**：纯 Host、无 client、无持久化、无 preset 竞争；卸载即还原，升级路径干净；
4. **可验证性**：状态端点直接给出挂载数、范围、`inherited`/`sessionless` 计数，问题可定位。

B 的价值在于「根因修法 + 按会话选审查模型」。如果以后需要**为审查单独选模型**，或者上游长期不修
`sessionId` 且我们决定接管 Auto preset，再按 B 的最小改动清单移植；当前不值得为此承担 fork 成本。

最终实现：见 [02-设计与实现.md](02-设计与实现.md)。它按 A 的机制重写并针对本机裁剪，同时保留 B 作为
备选路线的调研结论。
