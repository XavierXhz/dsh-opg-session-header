## 5. 自动审查路径实机探针（关键证据）

官方 auto-review 的评审调用有两个特征：**在 `tools/pre-execute` 内执行**、**`ctx.llm.stream` 不带
`sessionId`**。为在不切换权限 preset 的前提下验证这条路径，临时安装了
[`scripts/fixtures/opg-autoreview-probe`](../scripts/fixtures/opg-autoreview-probe/README.md)：

- 在 `tools/pre-execute`（与 auto-review 同一瀑布、同在 `agents.withInitiator` 作用域内）发一条
  `ctx.llm.stream({ provider: 'opencode-go', model: 'deepseek-v4.1-flash', … })`，**不带 sessionId**；
- 把结果写到 `/tmp/opg-autoreview-probe.json`；
- 安装后在下一次工具调用触发。

实测输出：

```json
{
  "at": "2026-10-23T14:15:25.217Z",
  "tool": "bash",
  "initiator": "session-<当前会话>",
  "ok": true,
  "text": "ok",
  "finish": "stop"
}
```

同一时刻的状态计数：

```json
{ "calls": 22, "scoped": 22, "attached": 22, "inherited": 1, "sessionless": 0 }
```

解读：

- `initiator` 拿到了当前会话 id → `agents.currentInitiator()` 回退在 `tools/pre-execute` 内确实可用；
- `inherited +1` 且 `sessionless` 保持 0 → 这条**无 sessionId** 的请求被插件补上了会话头；
- `ok: true / finish: stop` → 请求真实到达 OpenCode Go 网关并返回 200，没有 `400 MissingSessionID`。

探针随后已 `remove_bundle` 卸载，profile 中不残留。

### 尚未做的一步（可选的人工确认）

没有在本会话里真的把权限 preset 切成「自动审查」再触发工具调用（那会改变当前会话的权限状态）。
上面的探针已经复刻了 auto-review 的调用栈位置与请求形状。若要做最终人工确认：

1. 权限选择器切到 **自动审查（Auto）**；
2. 让 agent 执行一次 `bash`；
3. 再跑 `node scripts/status.mjs`：`counters.inherited` 应增长、`sessionless` 保持 0，会话里不应出现
   `Auto review … failed … MissingSessionID`。
