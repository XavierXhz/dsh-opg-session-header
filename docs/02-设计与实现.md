# 设计与实现

## 1. 目标与非目标

**目标**：在 dsh `0.2.1-rc.2` + `opencode-go` 的本机部署里，让官方
`@deepseek-ai/dsh-experimental-auto-review` 的评审请求不再因 `400 MissingSessionID` 失败；同时不破坏
主 agent 路径，不影响其它 provider。

**非目标**：不改 provider 配置、不写静态头、不接管 Auto preset、不提供审查模型选择器、不改磁盘上的
任何 dsh 文件。

## 2. 注入点

```text
agent loop / auto-review / session-title / compaction
        │  ctx.llm.stream(options)   ← 自动审查这里没有 sessionId
        ▼
LlmRuntime ──► route 注册表 ctx.llm.adapters (Map)
        │            │
        │            └─ adapter = PiAiAdapter
        ▼
PiAiAdapter#streamWithSnapshot(options, snapshot)     ← 本插件包在这里
        ▼
snapshot.models.streamSimple(model, context, options) ← 以及这里
        ▼
pi-ai 协议实现把 options.headers 合并进 HTTP 请求头（最后一步）
        ▼
OpenCode Go 网关
```

为什么不是 `globalThis.fetch`：fetch 补丁只能在「调用方传了 `sessionId`」时拿到会话上下文；自动审查
的 options 没有 `sessionId`，fetch 补丁必然空转。适配器分发点与调用方无关，且是 pi-ai 合并 headers
之前的最后一个可写位置。

## 3. 关键决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 会话头注入层 | pi-ai 适配器 `streamWithSnapshot` + `models.streamSimple` | 覆盖所有调用方；不依赖 fetch；不碰全局 |
| 无 sessionId 的辅助调用 | `agents.currentInitiator()?.session?.id`（可关） | 自动审查在 `tools/pre-execute` 内、处于 `withInitiator` 作用域；借真实会话 id，绝不伪造 |
| 路由范围 | 常量前缀 `opencode-go`（大小写不敏感） | 范围无法被配置写错；`opencode-zen`/`deepseek` 零触碰 |
| 取值 | `auto`：`openai-responses` 用原始 `session-<uuid>`，其余裸 UUID | 与 pi-ai 自带 `session_id` 对齐，避免一个会话裂成两个缓存桶 |
| 对请求对象 | 永远浅拷贝，不修改适配器的 options | 调用方/其它插件不会观察到副作用 |
| 幂等 | `Symbol.for('dsh-opg-session-header/{models,adapter}')` 记录钩子 | 重复扫描/HMR 不堆 wrapper；枚举不可见 |
| 晚注册路由 | `llm/adapters-updated` 事件 + 250/1000/3000ms 有界重扫 | route 由 settings 解析，常在本插件挂载之后才注册 |
| 类级覆盖 | 同时包适配器实例与原型 | HMR 后新建的适配器实例仍被覆盖 |
| 卸载 | `ctx.effect` disposer 还原每个对象 | 卸载/热重载后不留痕 |
| 诊断 | 只读 `GET /opg-session-header/status`，走 `connection.requestRejection` | 同源 + 登录；可在升级后快速自检 |
| 配置校验 | 未知键直接报错并说明固定范围 | 拼写错误不会被误当成「网关又坏了」 |

## 4. 会话 id 回退的安全边界

- 只借用 `agents.currentInitiator()?.session?.id`，**不从环境/URL/随机数生成**；
- 拿不到就保留部署原有 headers（不注入），并计入 `counters.sessionless`；
- `sessionlessFallback: false` 时完全不咨询回退缝；
- 头值是会话 UUID，不含凭据；诊断报告里对值做截断（`<masked-uuid>…`）。

## 5. 失败模式

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| `hooked.adapters: 0` | 本版本 `ctx.llm.adapters` 不可达或适配器形状变化 | 看 `diagnostics`；按 dsh 新内部面更新 `resolveAdapterRegistry`/`instrumentAdapter` |
| `routesInScope: []` | 注册表里没有 `opencode-go*` 路由 | 检查 provider 是否改名/未加载 |
| `counters.sessionless` 增长 | 有调用没拿到会话 id | 该调用不在 initiator 作用域内；评估是否扩展回退 |
| 插件加载失败 | `config` 未知键 / 导入失败 | 启动日志有 `opg-session-header:` 前缀的错误 |

## 7. 测试策略

- **单元层**：不依赖 dsh，覆盖所有纯函数与钩子安装/还原语义；
- **适配器层**：导入本机安装的 `@deepseek-ai/dsh-llm-pi-ai` 的 `PiAiAdapter` 与 pi-ai 的
  `fauxProvider`，断言 `SimpleStreamOptions.headers`——即 pi-ai 最后合并进 HTTP 请求头的同一张 map；
  对照用例先跑「未挂插件」再跑「已挂插件」，排除环境自带行为；
- **网关层**：真实 HTTP 请求证明缺头 400、带头 200；
- **实机层**：装进 web profile 后读 `/opg-session-header/status`，并用一次性探针插件在
  `tools/pre-execute`（与自动审查同一调用栈位置）发出无 sessionId 的 `ctx.llm.stream`，验证回退生效、
  网关不再 400。见 [03-验证记录.md](03-验证记录.md)。
